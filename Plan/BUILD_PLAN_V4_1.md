## Phase 1 — Fix copy-to-clipboard (root cause already diagnosed)

**Bug:** `makeCopyBox()` at app.js:20 and `generatePrompt()` at app.js:159 build the handler as
`onclick="copyText(${JSON.stringify(val)})"`. `JSON.stringify` emits **double quotes inside a double-quoted HTML attribute**, so the attribute terminates at the first `"` and the handler is malformed. This is exactly why the Doc Number Generator "Full reference" box and the ATEX Marking box don't copy, while symbol cards (which use `data-copy` + `symCopy(this)`, tab-symbols.js:25) and single-quoted `copyText('...')` calls (units, gland order codes) work fine.

**Fix pattern** — adopt the symbols approach, do not attempt cleverer quoting:

```js
<button class="copy-btn" data-copy="${escapeHtml(val)}" onclick="copyText(this.dataset.copy)">Copy</button>
```

`escapeHtml` (core-utils.js) already escapes `&`, `"`, `<`, `>` — attribute-safe.

**Apply to:** `makeCopyBox` (app.js:20 — fixes ATEX marking, doc number full-ref + number-only, cable description generator, gland part number generator) and the prompt output button (app.js:159 — note the prompt text is multi-line; `data-copy` handles newlines fine, but verify a generated prompt with quotes/newlines copies intact).

**Sweep:** grep `onclick="copyText(` across `js/` and `index.html`; convert any interpolated-value call sites to the `data-copy` pattern (hardcoded literals like `copyText('IP65')` may stay). Verify every copy surface listed in §Validation.

**Commit:** `Phase 1: fix copy-to-clipboard attribute escaping`

## Phase 6 — IS Loop Calculation tab (new feature)

New **top-level nav tab** (Mark confirmed): insert after Wonder Tool, label `IS Loop`. Tab clause numbering shifts: 7 IS Loop, 8 NPT, 9 Prompts, 10 Recycle Bin — update kicker `n` values on those tabs accordingly.

**Reference:** `Plan/IS Loop Calculation (reduced).xlsx` (Mark's existing MTL-style worksheet) + IEC 60079-25 entity evaluation. The reduced sheet's formulas confirm the standard method — implement the standard method cleanly rather than mimicking the sheet's layout quirks.

### 6.1 Inputs

- **Project / loop details:** loop tag, description, project no, doc no, rev, by, date. Persist per-field in localStorage (`met_is_*`, mirror the `met_wt_proj_*` pattern) and include in export/import (prefix scan like `wtProjKeys`).
- **Barrier / isolator (source):** manufacturer, model, certificate number, channel config note; entity parameters **Uo (V), Io (mA), Po (W), Co (µF), Lo (mH)**, plus optional **Lo/Ro (µH/Ω)**.
- **Field instrument (load):** tag, manufacturer, model, certificate number; **Ui (V), Ii (mA), Pi (W), Ci (nF), Li (µH or mH)**.
- **Cable — up to 3 segments** (multi-segment runs, e.g. multicore to JB then single pair). Each segment row:
  - Cable type dropdown populated from the instrument-cable electrical data **already in `js/data-cable.js` (`INSTR_ELECTRICAL`, line 292)**: shielded/unshielded × 0.75/1.5/2.5 mm² (+ the special large-fill entries) — each carries cap (nF/km), ind (mH/km), loop resistance (Ω/km), L/R (µH/Ω). Dropdown selection auto-fills the per-km values (read-only display).
  - A **Manual entry** option that unlocks the per-km fields for non-NEK606 cables.
  - Length (m). Segment totals: `C = len/1000 × cap`, `L = len/1000 × ind`, `R = len/1000 × r`.
- **Unit convenience (Mark's "baked-in converter"):** every capacitance input gets a unit select (pF / nF / µF) and every inductance input (µH / mH) — values normalised internally (suggest nF and µH as the internal base). Show the normalised value beside the field so unit mistakes are visible.

### 6.2 Calculation & verdicts

Standard entity checks, each rendered as a `.spec` row with a `.badge pass` / `.badge fail`:

| Check | Rule |
|---|---|
| Voltage | Uo ≤ Ui |
| Current | Io ≤ Ii |
| Power | Po ≤ Pi |
| Capacitance | Ci + ΣC_cable ≤ Co |
| Inductance | Li + ΣL_cable ≤ Lo |
| L/R alternative | If Lo/Ro given and inductance check fails: pass if every cable segment's L/R ≤ Lo/Ro (show as separate advisory row) |

Overall verdict badge: LOOP OK / DOES NOT COMPLY. Also display total cable R (Ω) informatively. Footnote (from Mark's sheet, keep it): *"For two-channel barriers the combined voltage, current and power must be calculated — refer to the barrier manufacturer if required."* Add the standard M.E.T. disclaimer note that IS loop approval requires verification by a competent person against the actual certificates.

### 6.3 Output

**Generate PDF** button producing a formal worksheet in the same v4 datasheet style built in Phase 5 (reuse the print-iframe helper and CSS — factor them so both tools share one implementation). Sections: title block (project/loop details) → 1 Barrier → 2 Instrument → 3 Cable segments table → 4 Entity comparison table with per-row verdicts → 5 Overall verdict → disclaimer + footer. This document goes into client documentation packages — it must stand alone (all entered data visible, units explicit, certificate numbers shown).

**Code layout:** new `js/tabs/tab-isloop.js` + tab markup in index.html + init call in app.js DOMContentLoaded. No changes to existing `INSTR_ELECTRICAL` values.
